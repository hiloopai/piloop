---
title: Reviewing a campaign
description: Check that the gains are real, that no agent gamed the evaluation, and where the time and tokens went.
---

A campaign can end with a better number that does not hold up. Review a campaign before you trust its result.

## With a coding agent

Open Claude Code, Codex or pi in the campaign repo and ask:

```text
review the piloop campaign
```

The agent follows the `piloop-review` skill. While it reviews, it opens the database read-only and changes nothing in
the running campaign. It answers four questions, in this order:

1. **Is the result real?** The trajectory of the best, the noise between sibling candidates, and whether the gains
   hold on data that no agent tuned against.
2. **Did any agent game the evaluation?** Edits to frozen files, reads of labels or per-unit results, and tuning
   against the evaluate command.
3. **What did it cost?** Tokens and time for each role, and the work that produced nothing.
4. **Whose fault is each failure?** The model, the harness, the environment, or the setup of the campaign.

It tags each claim as measured or inferred. It ends with a report, bug reports for problems in the tools, and inbox
items for the decisions that only you can take. It posts the inbox items as `escalation` comments on the campaign.

## By hand

The trajectory of the best and every new best:

```bash
piloop status my-campaign
piloop history my-campaign     # the new bests, each with its gain over its parent
```

The commit of a candidate, and its diff from its parent:

```bash
piloop sql "SELECT revision, summary, excluded_reason FROM candidates WHERE id = 42"
git show <revision>
```

Check that the best changed no frozen file, such as the evaluate command or the data:

```bash
git diff --stat <baseline-sha> <best-sha> -- evaluate.py data/
```

<Warning>
  An evaluator is defined by the evaluate command, the names and directions of the metrics and the `link` paths, not
  by the contents of `evaluate.py` or of the linked files. An implementer that edits `evaluate.py` changes the score without
  a new evaluator. Check the diff of the best, and of each candidate that may be best.
</Warning>

Read the [session](/concepts/roles#sessions) of an agent, its harness's own file:

```bash
piloop sql "SELECT id, kind, session_file FROM agent_sessions WHERE campaign_id = 1"
piloop cas get <session_file> > session.jsonl
```

Tokens and time for each role and harness:

```bash
piloop sql "SELECT kind, harness, COUNT(*) AS agents, SUM(usage->>'$.total') AS tokens FROM agent_sessions WHERE campaign_id = 1 GROUP BY kind, harness"
```

Who excluded a candidate or changed a status, other than the daemon:

```bash
piloop sql "SELECT at, actor, kind, payload FROM events WHERE kind IN ('candidate.excluded_reason', 'campaign.status') AND actor != 'daemon'"
```
