An MCP server gives an agent extra tools, such as web search. Define each server once in `piloop.toml`, and list it
in the roles that need it. piloop gives the servers to each harness in that harness's own format.

## Define a server

A server is either streamable HTTP (`provider = "http"`) or stdio (`provider = "stdio"`):

```toml
[plugins.mcp_server.exa]
provider = "http"
url = "https://mcp.exa.ai/mcp?tools=web_search_exa,web_fetch_exa"
headers_env = { "x-api-key" = "EXA_API_KEY" }

[plugins.mcp_server.firecrawl]
provider = "http"
url = "https://mcp.firecrawl.dev/v2/mcp"
bearer_token_env = "FIRECRAWL_API_KEY"

[plugins.mcp_server.xai]
provider = "stdio"
command = ["python3", "/path/to/piloop/scripts/xai_search_mcp.py", "grok-4.7", "--max-usd", "1"]
env = ["XAI_API_KEY"]

[plugins.role.research]
mcp = ["exa", "firecrawl", "xai"]
```

Whether a harness takes servers can depend on the runtime of the role. See
[what each harness gets](#what-each-harness-gets).

A role gets no servers unless its `mcp` key lists them. The [configuration
reference](/reference/configuration) has every key. A package can ship a server of its own, with its defaults, as a
provider of `mcp_server`.

## Keys stay out of the file

A server names the environment variables that hold its keys. It never holds a key. So `piloop.toml` is safe to
commit.

Each variable is the name of a [secret](/guides/secrets), which piloop puts in the agent's environment. The harness
then puts the value into the header or into the server's environment. A secret that is not set makes the launch fail,
with an error that names it. `piloop doctor` lists the missing secrets by name.

<Warning>
  The keys are in the agent's environment. An agent can read them with its shell tool. Codex agents are the exception:
  piloop removes the role's variables from the environment of Codex's shell tool.
</Warning>

## What each harness gets

Each built-in harness puts the role's servers at the `{mcp}` element of its command:

- **Claude Code**: `--strict-mcp-config` and an inline `--mcp-config`.
- **Codex**: every server of your Codex configuration is turned off, and the role's servers are added. A piloop
  server with the same name as one of yours makes the launch fail.
- **pi**: through `pi-mcp-adapter` in exclusive mode. This works only when pi's own extensions are off.

So the agents see only the role's servers, never the servers in your own configuration.

<Harnesses />

`piloop init` refuses a role that lists servers when a harness of its rotation cannot take them. Then leave that
harness out of the role's rotation, for example `harnesses = ["claude", "codex"]` under `[plugins.role.research]`.

A [harness of your own](/plugins/agents#harnesses) takes servers when its command has an `{mcp}`
element and it names a provider that takes them, such as `provider = "claude"`.

## The X search server

piloop includes a small stdio server, `scripts/xai_search_mcp.py`, with one tool, `x_search`. It searches recent posts
on X through xAI's API, and uses only the Python standard library.

```bash
XAI_API_KEY=… python3 scripts/xai_search_mcp.py <model> [--max-usd 1] [--max-tool-calls 10]
```

Each call costs money. The server limits the spend of one agent session: each reply states the cost of the call and
the total so far, and the server refuses every call after the total reaches `--max-usd`. `--max-tool-calls` limits
the searches of one call. The campaign's `hold_at` does not see this cost, so set `--max-usd`.

Use the script from a clone of the piloop repo. It is not part of the installed CLI.
