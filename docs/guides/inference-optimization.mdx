This campaign makes a model serve faster while its output stays the same. Its example serves a small model on a CPU,
so it runs on a laptop:

```bash
piloop init --example inference ~/piloop-inference
cd ~/piloop-inference
```

```text
campaign inference #1 registered; measuring baseline candidate#1 (`piloop eval queue` shows it; Ctrl-C stops only the wait)
baseline candidate#1: tokens 512, seconds 5.443, match 1, p50_ms 1433, p95_ms 1461
```

The implementers edit `server.py`, the inference server. The baseline recomputes the whole context for each new token.

## The evaluate command

`evaluate.py` starts `server.py` in its own process and load-tests it from outside. It writes one line for each rung of
the [evaluation ladder](/concepts/campaigns#the-evaluation-ladder), then one for the full benchmark:

```bash
python3 evaluate.py
```

```text
{"rung": "smoke", "metrics": {"tokens": 16, "seconds": 0.0835, "match": 1.0, "p50_ms": 83.52, "p95_ms": 83.52}}
{"rung": "load", "metrics": {"tokens": 128, "seconds": 1.4527, "match": 1.0, "p50_ms": 573.12, "p95_ms": 879.54}}
{"status": "ok", "score": 143.62, "direction": "higher", "metrics": {"tokens": 512, "seconds": 3.565, "match": 1.0, "p50_ms": 617.06, "p95_ms": 1865.05}}
```

- Each rung sends its requests again until it has run for a minimum time. A fixed number of requests would take
  milliseconds once the server is much faster, and noise would decide the score.
- `tokens` ÷ `seconds` is the throughput at the rung's concurrency.
- `match` is the share of the checked tokens that equal the reference decoder's: the quality.

For a real model, start your server (vLLM, SGLang or your own) in the evaluate command, wait until it is healthy, and
drive it at a fixed concurrency. Score quality on a fixed prompt set against the outputs of a reference build.

## The metrics

```toml
[[metrics]]
name = "tokens_per_s"
direction = "higher"
role = "primary"
ratio = { numerator = "tokens", denominator = "seconds" }

[[metrics]]
name = "tokens"
direction = "higher"

[[metrics]]
name = "seconds"
direction = "lower"

[[metrics]]
name = "match"                     # the quality: the share of checked tokens that equal the reference
direction = "higher"
role = "guardrail"
margin = 0.01
floor = 0.98

[[metrics]]
name = "p95_ms"
direction = "lower"
role = "guardrail"
fraction = 0.25                    # timing noise: up to 25% slower than the baseline still holds

[[metrics]]
name = "p50_ms"
direction = "lower"

[[ladder]]
name = "smoke"                     # 2 requests: does it serve the right tokens?
stop = { match = { floor = 0.9 } }

[[ladder]]
name = "load"                      # 8 requests at concurrency 4 for 0.5 s: is it not much slower?
stop = { p50_ms = { fraction = 0.5 } }
```

- **Throughput is a [ratio](/concepts/campaigns#ratio-metrics).** A rung that runs for a fixed time serves a different
  number of tokens on each candidate, and the ratio still compares them.
- **Noise.** A candidate whose first score beats the best is evaluated `noise_runs` times before it can be the best.
  The tolerances are wider than the noise.
- **Quality.** `match` may drop by `margin` from the baseline, and never below `floor`. An approximation that changes a
  few tokens can be the best. One that changes many cannot.
- **The ladder.** The smoke rung stops a server that gives wrong tokens in seconds. The load rung stops a slow one
  before the full benchmark:

```text
candidate#5: stopped at a rung of the ladder: p50_ms 42.65 vs 20.5 (+22.15; fraction 0.5)
```

## Run the benchmark on GPUs

On a real model, the agents run on the server and the evaluations on GPU workers. In the server's `config.toml`:

```toml
[plugins.executor]
provider = "workers"

[plugins.executor.pools.serve]
agents = 4
slots = { evaluation = 0 }         # the server runs no benchmark

[plugins.executor.pools.gpu]
agents = 0
slots = { evaluation = 1 }         # one benchmark per GPU: two would slow each other
runners = ["process"]

[plugins.executor.pools.gpu.provisioner]
max = 2

[plugins.executor.pools.gpu.provisioner.compute]
provider = "modal"
image = "ghcr.io/acme/piloop-worker:0.3"
gpu = "H100"
```

[Workers](/guides/workers) shows the network, the CAS and the tokens that the workers need.

## Plugins for this work

The package [`examples/plugins/inference`](https://github.com/hiloopai/piloop/tree/main/examples/plugins/inference)
adds three providers. Install it next to piloop, select each one in `piloop.toml`, and run `piloop init` again:

```bash
uv tool install piloop --with ./examples/plugins/inference
piloop plugins
```

`gpu_hours`, a [fact source](/plugins/rules#fact-sources), prices the evaluations' wall time, so `hold_at` holds the
campaign at a GPU budget:

<ExampleGpuHours />

```toml
[plugins.fact_source]
use = ["campaign", "optimization", "gpu_hours"]

[plugins.fact_source.gpu_hours]
gpus = 1
usd_per_gpu_hour = 2.5

[plugins.stop_rule]
hold_at = { gpu_usd = 50 }         # nothing new starts past 50 USD of GPU time
```

`min_speedup`, a [best rule](/plugins/rules#best-rules), refuses a best that is less than a fraction faster than the
baseline, so a lucky few percent never makes the best:

<ExampleMinSpeedup />

```toml
[plugins.best_rule]
provider = "min_speedup"
min_speedup = 0.05
```

`latency`, a [section](/plugins/agents#sections), shows each implementer what the latest candidates did to the tail:

<ExampleLatency />

```toml
[plugins.section.latency]
metrics = ["p50_ms", "p95_ms", "match"]
```
