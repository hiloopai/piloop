title: Notifications
description: Get a Slack message when an escalation waits for you.
---

A **notifier** tells you, outside piloop, that an inbox item needs you. To post to a Slack channel, create an
[incoming webhook](https://docs.slack.dev/messaging/sending-messages-using-incoming-webhooks), store its URL as a
[secret](/guides/secrets), and name `slack` in `config.toml`:

```bash
printf %s "$SLACK_WEBHOOK_URL" | piloop secret set SLACK_WEBHOOK_URL
```

```text
SLACK_WEBHOOK_URL set for the home
```

```toml
# $PILOOP_HOME/config.toml
[plugins.notifier]
use = ["slack"]
```

`config.toml` holds the defaults of every campaign's notifiers. Run `piloop restart`, then `piloop init` each
campaign, which stores them in its config. The next escalation posts this to the channel:

```text
:rotating_light: *enwik8* · escalation comment#1 · P1 · from implementer#12
Run 41's evaluation takes 3 h, over the 1 h timeout. Raise the timeout, or drop the idea?
`piloop inbox show 1`
```

## What is sent

- An item is sent when it is an escalation or has priority 0, nobody has acknowledged it, and a person did not write
  it.
- Each pass of the daemon sends one message with every new item. `slack_app` posts each item on its own.
- An item that still waits a day later is sent again as a reminder, while its campaign is active.
  `piloop inbox ack` ends the reminders.
- piloop records each send as a `notification.sent` event on the item, so a restart sends nothing twice.

## When a send fails

piloop records a `notification.failed` event with the error, and tries again after 1 minute, then 2, 4 and so on, up
to an hour. Slack's `Retry-After` wins. The first failure also puts a note in your inbox, under the item that was not
sent.

## A channel of your own

Name an instance to change its keys. A notifier that `use` does not name is an error.

```toml
[plugins.notifier]
use = ["team"]

[plugins.notifier.team]
provider = "slack"
webhook = { secret = "TEAM_WEBHOOK" }
link = "https://piloop.example.com/inbox/{comment}"
people = { "alice@example.com" = "U0123ABC" }
remind_every = "PT12H"
template = "{mark} *{campaign}* {kind} from {author}{mention}\n{body}\n{link}"
```

`template` sets how the message shows each item, from a fixed set of placeholders: an unknown one is an error when
the file loads. On a shared server, `people` pings the person who added the campaign, by the name that the server
gives them.
The [configuration reference](/reference/configuration#plugins) lists every key of `slack`.

## Answer from Slack

`slack_app` posts as a Slack app, and reads the answers in the thread of each post. A reply in the thread is your
message to the orchestrator on that item, signed as you. A :white_check_mark: on the post acknowledges the item. `idea: <hunch>` files a
seed. An edit of your reply changes it, and the orchestrator gets the new text as news. piloop's own answers in the thread go back to it.

```toml
[plugins.notifier]
use = ["team"]

[plugins.notifier.team]
provider = "slack_app"
channel = "C0CCLEHFNQN"
people = { "alice@example.com" = "U0123ABC" }
```

1. Install the extra: `uv tool install --reinstall 'piloop[slack]'`.
2. Create a Slack app with Socket Mode on. Give its bot the scopes `chat:write`, `channels:history`, `groups:history`
   and `reactions:read`, and subscribe it to `message.channels`, `message.groups` and `reaction_added`.
3. Store its two tokens: `piloop secret set SLACK_BOT_TOKEN` (`xoxb-…`) and `piloop secret set SLACK_APP_TOKEN`
   (`xapp-…`, with `connections:write`).
4. Invite the bot to the channel: `/invite @<app>`. Slack sends it no replies from a channel it is not in.

Socket Mode is a connection out from the daemon, so it needs no public URL. piloop confirms each answer to you, in a
message that only you see: `piloop recorded this as comment#3, a reply to comment#1`. Only `people` can answer:
piloop tells anyone else why, the same way. A reply outside a post's thread gets a hint.

## A campaign's own notifiers

A campaign's `piloop.toml` can set `[plugins.notifier]` over the defaults of `config.toml`. Its `use` replaces the
home's for the items of that campaign. Each item goes once to each notifier of one `use`: an item of no campaign goes
to those of `config.toml`. To post a campaign's items to its own channel with its own bot token:

```bash
printf %s "$TOKEN" | piloop secret set ENWIK8_BOT_TOKEN --campaign enwik8
```

```toml
# piloop.toml
[plugins.notifier]
use = ["team"]

[plugins.notifier.team]
provider = "slack_app"
channel = "C0ENWIK8"
token = { secret = "ENWIK8_BOT_TOKEN" }
```

A notifier reads its secrets as the campaign's agents do: the campaign's secret wins over the home's of the same
name. Then run `piloop init` on the campaign.

The `slack_app` instances with the same app token share one Socket Mode connection, whichever campaigns use them:
Slack splits an app's events across its open connections. piloop opens, closes and reopens the connections when a
campaign or a secret changes, with no restart.

To write a notifier for another service, see [Infrastructure](/plugins/infrastructure#notifiers).
