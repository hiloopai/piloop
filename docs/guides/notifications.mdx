---
title: Notifications
description: Get a Slack message when an escalation waits for you, and answer it from Slack.
---

A **notifier** tells you, outside piloop, that an inbox item needs you. To post to a Slack channel, create an
[incoming webhook](https://docs.slack.dev/messaging/sending-messages-using-incoming-webhooks), store its URL as a
[secret](/guides/secrets), and name `slack` in `config.toml`:

```bash
printf %s "$SLACK_WEBHOOK_URL" | piloop secret set SLACK_WEBHOOK_URL
```

```toml
# $PILOOP_HOME/config.toml
[plugins.notifier]
use = ["slack"]
```

`config.toml` holds the defaults of every campaign's notifiers. Run `piloop restart`, then `piloop init` each campaign.
The next escalation posts this to the channel:

```text
:rotating_light: *enwik8* · escalation comment#1 · P1 · from implementer#12
Run 41's evaluation takes 3 h, over the 1 h timeout. Raise the timeout, or drop the idea?
`piloop inbox show 1`
```

## What is sent

- An escalation or a priority-0 item that no person has acknowledged and nobody has answered, and that a person did
  not write. An orchestrator's ack does not stop it.
- Only priorities 0 and 1, unless `max_priority` says otherwise: `4` sends every priority.
- A reminder a day later while the item waits and its campaign is active. `piloop inbox ack` ends the reminders.
- Nothing twice: each send is a `notification.sent` event. A failed send is retried with a doubling wait up to an
  hour, and the first failure puts a note in your inbox.

## A channel of your own

Name an instance to change its keys:

```toml
[plugins.notifier]
use = ["team"]

[plugins.notifier.team]
provider = "slack"
webhook = { secret = "TEAM_WEBHOOK" }
link = "https://piloop.example.com/inbox/{comment}"
people = { "alice@example.com" = "U0123ABC" }
remind_every = "PT12H"
template = "{mark} *{campaign}* {kind} from {author}{mention}\n{body}\n{link}"
```

`template` takes a fixed set of placeholders: an unknown one is an error when the file loads. `people` pings the
person who added the campaign. The [configuration reference](/reference/configuration#plugins) lists every key.

## Answer from Slack

`slack_app` posts each item as a Slack app, and reads the answers in its thread:

- A button for each choice of an escalation answers it, as `piloop inbox choose` does, signed as you.
- A reply in the thread is your message to the orchestrator on that item. An edit of it sends the new text.
- A :white_check_mark: on the post acknowledges the item.
- `idea: <title>` adds an open idea.

Only `people` can answer. piloop confirms each answer in a message that only you see.

```toml
[plugins.notifier]
use = ["team"]

[plugins.notifier.team]
provider = "slack_app"
channel = "C0CCLEHFNQN"
people = { "alice@example.com" = "U0123ABC" }
```

1. Install the extra: `uv tool install --reinstall 'piloop[slack]'`.
2. Create a Slack app with Socket Mode on. Give its bot the scopes `chat:write`, `channels:history`, `groups:history`
   and `reactions:read`, and subscribe it to `message.channels`, `message.groups` and `reaction_added`. Turn on
   Interactivity, for the buttons. Socket Mode needs no public URL.
3. Store its two tokens: `piloop secret set SLACK_BOT_TOKEN` (`xoxb-…`) and `piloop secret set SLACK_APP_TOKEN`
   (`xapp-…`, with `connections:write`).
4. Invite the bot to the channel: `/invite @<app>`.

## A campaign's own notifiers

A campaign's `piloop.toml` can set `[plugins.notifier]`. Its `use` replaces the home's for that campaign's items. To
post them to their own channel with their own bot token:

```bash
printf %s "$TOKEN" | piloop secret set ENWIK8_BOT_TOKEN --campaign enwik8
```

```toml
# piloop.toml
[plugins.notifier]
use = ["team"]

[plugins.notifier.team]
provider = "slack_app"
channel = "C0ENWIK8"
token = { secret = "ENWIK8_BOT_TOKEN" }
```

Then run `piloop init` on the campaign. The `slack_app` instances with the same app token share one Socket Mode
connection. To write a notifier for another service, see [Infrastructure](/plugins/infrastructure#notifiers).
