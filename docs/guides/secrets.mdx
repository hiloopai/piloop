---
title: Secrets
description: Give agents the API keys that MCP servers and model gateways need, without a key in any file.
---

`piloop secret set` stores a key. Each agent that starts after it gets the key in its environment, under the
secret's name:

```bash
printf %s "$EXA_API_KEY" | piloop secret set EXA_API_KEY --campaign enwik8
piloop secret list
```

```text
EXA_API_KEY set for campaign enwik8

  name          of       set                by
 ─────────────────────────────────────────────────
  EXA_API_KEY   enwik8   2026-10-26 17:16   human
```

On a terminal, `piloop secret set EXA_API_KEY` asks for the value and does not show it. `piloop secret list` never
shows a value. `piloop secret rm EXA_API_KEY` deletes it.

`piloop secret` goes through the daemon's API, here as on a server. Start the daemon first, with
`piloop serve --detach`. A paused campaign stays paused.

## Who gets a secret

- Without `--campaign`, a secret is the home's, for every campaign. A campaign's secret wins over the home's of the
  same name.
- An agent gets only the secrets that its job names: the variables of its role's [MCP servers](/guides/mcp-servers),
  and the secrets in its harness's `env`.
- A [worker on another machine](/guides/workers) gets the values from the server when it starts the job.

## Who sets a secret

- On the home's machine, you set any secret.
- With a [token](/reference/cli#piloop-token), `act` access sets and deletes a campaign's secrets, and `admin` access
  also the home's.
- An agent sets and deletes the secrets of its own campaign, and no other.

<Warning>
  An agent can read the keys in its environment. The database of the home holds the values in plain text: `piloop sql`
  cannot read them, but a copy of the database file can.
</Warning>

## Model access

`[plugins.harness.<name>] env` gives the agents of a harness more variables, each a value or a secret. To send Claude Code
through a model gateway:

```toml
[plugins.harness.claude.env]
ANTHROPIC_BASE_URL = "https://gw.example.com"
ANTHROPIC_API_KEY = { secret = "ANTHROPIC_API_KEY" }
```

The table changes only `env`, and the other keys of the built-in harness stay. Without `env`, an agent uses the login
of the machine that runs it.

Codex does not read a base URL from its environment. Give it a model provider in `config`, which piloop passes to
Codex as `-c` flags:

```toml
[plugins.harness.codex.config]
model_provider = "gateway"
model_providers.gateway = { name = "gateway", base_url = "https://gw.example.com/v1", env_key = "GATEWAY_KEY", wire_api = "responses" }

[plugins.harness.codex.env]
GATEWAY_KEY = { secret = "GATEWAY_KEY" }
```

Codex sends the value of the variable that `env_key` names as its bearer token. `config` takes any key of Codex's
`config.toml`.
