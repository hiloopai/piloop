---
title: Running for days
description: Run the daemon in the background or under a service manager, and restart it without losing work.
---

`piloop serve` is the daemon: it starts the agents, scores the commits and enforces the limits of every campaign. One
daemon runs for each `PILOOP_HOME`.

```bash
piloop serve --detach
piloop restart
piloop stop
```

```text
daemon started: pid 586609, log ~/.piloop/serve.log
daemon pid 586609 restarted
daemon pid 586609 stopped
```

| Command | What happens to the agents |
|---|---|
| `piloop restart` | They keep running. The same process starts the installed code again, and connects to each agent. |
| `piloop stop` | They stop. Their runs are not attempts: the ideas go back to `open`. Their commits stay as `recovered` candidates. |
| A crash | Like a restart: the next daemon connects to the agents that still run. |

The campaigns stay active through all three. To hold one campaign and leave the others running:

```bash
piloop pause enwik8 --reason "the GPU trains a model"
piloop resume enwik8
```

```text
campaign enwik8 paused (launches): the GPU trains a model; running work goes on; `piloop resume enwik8` ends it
campaign enwik8 resumed
```

## Under a service manager

`piloop service-unit` prints a unit file. It installs nothing.

<Tabs>
  <Tab title="Linux (systemd)">
    ```bash
    piloop service-unit > ~/.config/systemd/user/piloop.service
    systemctl --user enable --now piloop
    ```
  </Tab>
  <Tab title="macOS (launchd)">
    ```bash
    piloop service-unit > ~/Library/LaunchAgents/dev.piloop.serve.plist
    launchctl load -w ~/Library/LaunchAgents/dev.piloop.serve.plist
    ```
  </Tab>
</Tabs>

```text
[Unit]
Description=piloop autoresearch daemon

[Service]
ExecStart=/home/me/.local/share/uv/tools/piloop/bin/python -P -m piloop serve
Restart=on-failure
Environment="PILOOP_HOME=/home/me/.piloop"
Environment="PATH=…"

[Install]
WantedBy=default.target
```

- The unit carries your current `PATH`, so the daemon finds the harness CLIs, and the `PILOOP_*` and harness variables
  of your shell, such as `CLAUDE_CONFIG_DIR`. Set them before you run `piloop service-unit`. API keys are
  [secrets](/guides/secrets).
- Start and stop the daemon with the service manager. Never run `piloop serve --detach` beside it.
- `piloop restart` and `piloop upgrade` keep the daemon under the service manager.
- After you change the unit, reload it: `systemctl --user daemon-reload`, then `systemctl --user restart piloop`.

## Logs

The daemon writes one line for each span to `~/.piloop/serve.log`. Set `OTEL_EXPORTER_OTLP_ENDPOINT` to send the spans
to an OpenTelemetry collector too. A `piloop.db.pool_wait` span says that a thread waited 30 seconds for a database
connection, with how many were in use: the disk stalled, and the daemon waits it out. No run fails of it. The `events` table is the easiest record to query:

```bash
piloop sql "SELECT at, actor, kind, payload FROM events ORDER BY id DESC LIMIT 20"
```
