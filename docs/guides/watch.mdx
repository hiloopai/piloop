---
title: Watching a campaign
description: piloop watch shows the campaign on one screen, with keys to act on it.
---

`piloop watch` is a terminal app over piloop's API. It shows every campaign, or one campaign with
`piloop watch <campaign>`. It follows the [event feed](/reference/event-feed) and reads again what each event changes.
With `PILOOP_SERVER` set, it shows the campaigns of that server (see [Run piloop on a server](/guides/remote-server)).
It is also an example of a UI built on the API: see [Build a UI on piloop](/guides/build-a-ui). `[watch]` in
`config.toml` sets how much it shows ([configuration](/reference/configuration#watch)).

## The screens

The first screen lists every campaign, the active ones first. Press `enter` to open one, and `esc` to come back.

It shows one row per campaign: its status, the head and its gain over the baseline, the live agents, the ready ideas, the
inbox, the tokens and the last event.

A campaign has a header, five panels on the left, and the main pane on the right, which shows the selected row in
full:

The header shows the campaign's state, then the first section of its `[plugins.section] use`: by default the head, the
number of keeps and the tokens. The Status panel lists every section, such as the goal and the progress against the
stop rule.

## Panels and keys

These keys work on the screen of a campaign. `?` and `q` also work on the list of campaigns.

| Key | Action |
|---|---|
| `1` to `5`, `tab` | Move between the panels. |
| `0` | Move into the main pane, to scroll it. |
| `↑` `↓`, `j` `k` | Select a row. |
| `/` | Filter the panel. `enter` applies the filter, `esc` clears it. |
| `?` | List the keys of the panel. |
| `esc` | Go back to the list of campaigns. |
| `q` | Quit. |

| Panel | Rows | Main pane | Keys |
|---|---|---|---|
| [1] Inbox | The unacknowledged items, most urgent first, without the items that you wrote. | The item and its thread. | `a` acknowledge, `A` acknowledge every item shown, `r` reply |
| [2] Agents | The starting and running agents. | The agent, its task, and its last 60 lines of output. | `s` steer |
| [3] Ideas | Seeds, then proposed, ready, scheduled and parked ideas, and by priority within each status. | Hypothesis, plan, links, runs and comments. | `y` approve, `p` park, `x` reject, `+` `-` priority |
| [4] Candidates | The nodes of the campaign's lineage (`GET /v1/campaigns/{campaign}/lineage`), newest first. The title shows the head after each keep as a sparkline. | Verdict and reason, links, metrics against the parent, summary. | none |
| [5] Status | The sections of the campaign's `[plugins.section] use`. | The section. | none |

## What the keys write

Each key calls the route that the CLI calls, as `PILOOP_ACTOR`, which is `human` unless you set it. The `events` table
records the write like any other.

- **Acknowledge** does what `piloop inbox ack` does.
- **Reply** asks for the text and a priority (default 2). It writes a `decision` comment that replies to the first
  item of the thread. The orchestrator's next wait returns with it, and the orchestrator acknowledges it after it
  applies it.
- **Steer** queues text for the agent's next turn, as `piloop prompt` does.
- **Approve, park and reject** ask why. Each one writes the status change and a `note` on the idea with the reason.
  A seed cannot be approved: research develops it into an idea first (`piloop idea develop`).
