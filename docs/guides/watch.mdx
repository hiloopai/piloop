`piloop watch` is a terminal app over the database. It shows every project, or one project with
`piloop watch <project>`. It reads the database again whenever the daemon or an agent writes to it.

## Panels and keys

These keys work everywhere:

| Key | Action |
|---|---|
| `1` to `4`, `tab` | Move between the panels. |
| `0` | Move into the main pane, to scroll it. |
| `↑` `↓`, `j` `k` | Select a row. |
| `/` | Filter the panel. `enter` applies the filter, `esc` clears it. |
| `?` | List the keys of the panel. |
| `esc` | Go back to the list of projects. |
| `q` | Quit. |

| Panel | Rows | Main pane | Keys |
|---|---|---|---|
| [1] Inbox | The unacknowledged items, most urgent first, without the items that you wrote. | The item and its thread. | `a` acknowledge, `A` acknowledge every item shown, `r` reply |
| [2] Agents | The running agents: `●` working, `○` idle, `◐` waiting on a dialog. | The agent, its task, and its last 60 lines of output. | `enter` open its Herdr tab, `s` steer |
| [3] Ideas | Seeds, proposed, ready, scheduled and parked ideas, by priority. | Hypothesis, plan, links, runs and comments. | `y` approve, `p` park, `x` reject, `+` `-` priority |
| [4] Candidates | The candidates, newest first, then the imported references. The title shows the head after each keep as a sparkline. | Verdict and reason, metrics against the parent, summary. | none |

## What the keys write

Each key writes as `PILOOP_ACTOR`, which is `human` unless you set it. The events table records the write like any
other.

- **Acknowledge** does what `piloop inbox ack` does.
- **Reply** asks for the text and a priority (default 2). It writes a `decision` comment that replies to the first
  item of the thread. The orchestrator's next wait returns with it, and the orchestrator acknowledges it after it
  applies it.
- **Steer** types text into the agent's pane, as `piloop prompt` does. Herdr refuses while the agent waits on a
  dialog. Press `enter` to go to the agent's tab and answer the dialog.
- **Approve, park and reject** ask why. Each one writes the status change and a `note` on the idea with the reason.
  Approving a seed sends it to research first.

## In Herdr

With the Herdr runtime, piloop has its own Herdr session, `piloop`, with one workspace for each project. The first tab
of a workspace is `home`: a shell on the left and `piloop watch <project>` on the right. Each agent gets its own tab,
named after its role, its id and its idea:

```text
my-project
  home                                shell │ piloop watch
  worker-12 idea#5 Stacking with a meta-learner…
  research-7
  watchdog-13
```

`piloop attach <worker-id>` opens an agent's tab from any terminal.
