Each role has a table in `piloop.toml`. This one runs up to four implementers on two harnesses, for at most 30 minutes
each, and one research agent at a time:

```toml
[plugins.harness.claude]
model = "claude-opus-5-5"

[plugins.harness.codex]
model = "gpt-6.1-sol"

[plugins.role.implementer]
harnesses = ["claude", "codex"]
max_concurrent = 4
timeout = 1800

[plugins.role.research]
max_concurrent = 1
```

Run `piloop init` after you change it. To ask for one more agent of a role:

```bash
piloop launch enwik8 research --reason "second opinion on idea#2"
```

```text
agent_session#4 research requested for enwik8: second opinion on idea#2
```

Each agent is an **agent session**, with an id, a log and the tokens that it used. It signs its writes
`<role>#<id>`, such as `research#4`. The [configuration reference](/reference/configuration#roleconfig) lists every
key of a role.

## The built-in roles

| Role | What it does | When it starts |
|---|---|---|
| **implementer** | Implements one idea, commits, and writes a `finding`. Its commits are scored. | A ready idea and a free slot. |
| **research** | Develops seeds into ideas, and adds ideas where the head loses the most. | A new seed, a short backlog, or a stall. |
| **watchdog** | Investigates failures and reviews progress. Writes comments and seeds, never code. | A failed run, an agent dead at its start, every `interval` seconds when something is new, and once at the stop, for the closing report. |
| **scout** | Searches X, GitHub and arXiv for techniques, and files the best as seeds. | Every `interval` seconds. Off until you set it. |
| **orchestrator** | Answers messages and escalations, steers the work, and records its decisions. Each one resumes the session of the one before. | News for it, with the `news` trigger. Off until you set it: by default, you run your own [orchestrator](/concepts/orchestrator). |

The implementer **does runs**: it takes ideas from the queue. The others are **sweeps**: their triggers start them,
and nothing that they commit is scored.

## Triggers

A **trigger** is a condition that starts one more agent of a sweep. This watchdog only reviews the progress every hour,
and once when the campaign stops:

```toml
[plugins.role.watchdog]
triggers = ["cron", "stopped"]
interval = 3600
```

A role names its triggers. A trigger with parameters has a table, `[plugins.trigger.<name>]`: a built-in name, such as
`low_water`, changes that trigger for every role that names it, and a new name needs its `provider`. An empty list
turns a role's triggers off. These are built in:

## Define a role

A table with a new name defines a sweep. It needs `prompt`, the file that starts its brief, and `triggers`. This
reviewer reads each new keep:

```toml
[plugins.role.reviewer]
prompt = "briefs/reviewer.md"
triggers = ["new_keep"]
max_concurrent = 1
timeout = 900
files = "seeds"
writes = ["comments(finding) on a candidate", "seeds via idea seed"]

[plugins.trigger.new_keep]
provider = "sql"
when = "SELECT id FROM candidates WHERE campaign_id = :campaign AND verdict = 'keep' AND created_at > :since"
```

`:campaign` is the campaign's id, and `:since` is when the role's last agent started.

With `runs = true`, a new role does runs. It has the implementer's defaults. This one takes the cheap ideas:

```toml
[plugins.role.quick]
runs = true
takes = "priority >= 3"    # an SQL condition on the ideas table
harnesses = ["pi"]
timeout = 300
```

Your roles take their ideas first, and the implementer takes the rest. A keep of any role moves the head.

## Sections

A **section** is one part of what `piloop status` or a brief shows, such as `## Goal` or `## Queue`. Without a list,
each shows every section that declares it. `[plugins.section] use` lists those of `piloop status`, and a role's
`sections` those of its briefs, in order. A section with parameters has a table:

```toml
[plugins.section]
use = ["headline", "trajectory", "runs"]

[plugins.role.research]
sections = ["research_lessons", "goal", "queue", "pack"]

[plugins.section.research_lessons]
provider = "lessons"
budget = 800
```

## Harnesses

A **harness** is the coding agent CLI that an agent runs in. `use` in `[plugins.harness]` lists the ones that runs use
in turn. A `[plugins.harness.<name>]` table sets a harness's `model`, changes a built-in harness, or adds one:

```toml
[plugins.harness]
use = ["claude", "gateway", "mycli"]

[plugins.harness.claude]
model = "claude-opus-5-5"
max_concurrent = 2   # agents of this harness at once, all roles together

[plugins.harness.gateway]
provider = "claude"
model = "claude-opus-5-5"
env = { ANTHROPIC_BASE_URL = "https://gw.example.com" }

[plugins.harness.mycli]
model = "my-model"
executable = "mycli"
headless = ["--model", "{model}", "{prompt}"]
```

| Table | What it is |
|---|---|
| A built-in name, such as `[plugins.harness.claude]` | That harness, with the keys that the table changes. |
| A new name with `provider`, such as `gateway` | That provider over its defaults: Claude Code through a gateway. |
| A new name without `provider`, such as `mycli` | Its argv and nothing else: it takes no MCP servers, and records no tokens. |

A harness with a table of its own is in `use`, or in a role's `harnesses`: piloop refuses a table that no rotation
names.

## Runtimes

A **runtime** starts, steers and stops the agents' processes. `[plugins.runtime] use` sets it for the campaign, and
`[plugins.role.<name>] runtime` for one role.

## Watch and steer an agent

| Command | What it does |
|---|---|
| `piloop watch` | Shows the agents with their last output. |
| `piloop attach 12` | Prints the last 40 lines that agent 12 wrote. |
| `piloop prompt 12 "<text>"` | Sends text to the agent's next turn. |

A note on a sweep that has not started yet goes into its brief, under `# Notes`, and reaches it only there.

A run's brief, log and transcript are in `~/.piloop/runs/<run>/`, and a sweep's in `~/.piloop/agent_sessions/<id>/`.
When an agent ends, piloop ends every process that it started, such as a build server.

`agent_sessions.state` is where an agent is:

| State | Meaning |
|---|---|
| `requested` | Waits for a slot. |
| `starting`, `running` | Its process starts, then works. |
| `ending` | A stop or a cancel ends it. piloop refuses its finding from now on. |
| `exited`, `killed` | It ended by itself, or piloop ended it. |

## Sessions

piloop keeps each agent's **session**, the harness's file of its prompts, tool calls and reasoning, in the
[CAS](/concepts/archive#the-cas). It saves a snapshot at least every 30 seconds while the agent runs. To read the
session that made candidate 2:

```bash
piloop sql "SELECT s.id, s.session_file FROM agent_sessions s JOIN candidates c ON c.run_id = s.run_id WHERE c.id = 2"
piloop cas get <session_file> > session.jsonl
```

A plugin can add roles, triggers, sections and runtimes: see [Agents and sections](/plugins/agents).
