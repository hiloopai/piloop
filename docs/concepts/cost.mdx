`[plugins.stop_rule]` in `piloop.toml` says when a campaign stops:

```toml
[plugins.stop_rule]
max_runs = 20
max_tokens = 50_000_000
```

`piloop status enwik8` shows the progress against each limit:

```text
- Campaign: active. Progress: run 2/20 · 0.0h · 0/50.0M tok.
```

Any one limit stops the campaign. Without a limit, the campaign has no end. These are the limits of the built-in stop
rule, `limits`:

## What a stop does

The daemon tells the running implementers to commit and stop, ends them 10 minutes later, and scores what they
committed. `wrap_up_grace` in `[agents]` of `piloop.toml` or of the home's `config.toml` changes the 10 minutes. It drops the queued runs. Then the watchdog's closing review writes the closing report.

| Command | What it stops |
|---|---|
| `piloop campaign stop enwik8` | The campaign, as a limit does. |
| `piloop pause enwik8 --reason "<why>"` | New launches of one campaign, until `piloop resume enwik8`. |
| `piloop stop` | The daemon, not the campaigns: the next `piloop serve` continues them. |

To resume a stopped campaign, raise its limits and run `piloop init`.

## Tokens

When an agent ends, piloop reads its tokens from the harness's own session file, and writes them to
`agent_sessions.usage`:

```json
{"input": 120345, "output": 18230, "cache_read": 950112, "cache_write": 40211, "total": 1128898, "turns": 41, "source": "…"}
```

`input` is the input that the prompt cache did not serve. `max_tokens` limits the `total` of every agent of the
campaign. piloop has no price table, so it counts tokens, not money.

## Spend outside piloop

GPU time and paid APIs are **facts** that a **fact source** reads. The built-in `command` source runs a command that
writes `{"metrics": {"<name>": <value>}}` to `$PILOOP_RESULT_FILE`, and `hold_at` holds the campaign at a limit:

```toml
[plugins.stop_rule]
max_runs = 20
max_tokens = 50_000_000
hold_at = { spend = 1000 }                    # nothing new starts at this spend

[plugins.fact_source]
use = ["campaign", "optimization", "spend"]   # piloop's own facts, and the source below

[plugins.fact_source.spend]
provider = "command"
command = ["uv", "run", "python", "scripts/spend.py"]   # reports {"metrics": {"spend": 1012}}
metrics = ["spend"]
notices = { spend = [300, 600] }              # a note in the inbox as each one is passed
```

```text
- Campaign: active. Progress: run 2/20 · 0.0h · 0/50.0M tok · spend 1012/1000 (launches held: spend at its limit).
```

```text
comment#5 escalation on campaign#1 by daemon, 35s ago · p0, unacknowledged
Stop rule limits: spend reached its hold_at of 1000: nothing launches until you raise it and run piloop init
```

- The daemon reads the source every `interval` seconds (300 by default), at the repo's root, with the daemon's
  environment. Give it its keys as [secrets](/guides/secrets).
- A **hold** is not a stop. While the value is at its limit, or unknown, nothing new starts, and what runs finishes and
  is scored. An unknown value is never read as zero.
- To resume, raise the limit and run `piloop init`.
- `piloop campaign stop` stops a held campaign at once. `while_held` says whether its closing review runs anyway
  (`run`, the default), is skipped (`skip`), or waits for the hold to end (`wait`).

A plugin can add a fact source, such as a cloud's billing API, or another stop rule: see
[Rules and facts](/plugins/rules).
