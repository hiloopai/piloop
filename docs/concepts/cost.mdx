`[plugins.stop_rule]` in `piloop.toml` says when a campaign stops:

```toml
[plugins.stop_rule]
max_runs = 20
max_tokens = 50_000_000
```

`piloop status enwik8` shows the progress against each limit:

```text
- Campaign: active. Progress: run 2/20 · 0.0h · 0/50.0M tok.
```

Any one limit stops the campaign. Without a limit, the campaign has no end. These are the limits of the built-in stop
rule, `limits`:

## What a stop does

The daemon tells the running implementers to commit and stop, ends them 10 minutes later, and scores what they
committed. `wrap_up_grace` in `[agents]` of `piloop.toml` or of the home's `config.toml` changes the 10 minutes. It drops the queued runs. Then the watchdog's closing review writes the closing report.

| Command | What it stops |
|---|---|
| `piloop campaign stop enwik8` | The campaign, as a limit does. |
| `piloop pause enwik8 --reason "<why>"` | New launches of one campaign, until `piloop resume enwik8`. |
| `piloop stop` | The daemon, not the campaigns: the next `piloop serve` continues them. |

To resume a stopped campaign, reopen it (`piloop campaign reopen`): its runs, hours and tokens count from the reopen.
Or raise its limits and run `piloop init`. See [Reopen, fork and retire](/concepts/campaigns#reopen-fork-and-retire).

## Tokens

When an agent ends, piloop reads its tokens from the harness's own session file, and writes them to
`agent_sessions.usage`:

```json
{"input": 120345, "output": 18230, "cache_read": 950112, "cache_write": 40211, "total": 1128898, "turns": 41, "source": "…"}
```

`input` is the input that the prompt cache did not serve. `max_tokens` limits the `total` of every agent of the
campaign.

## What a campaign spent

The `spend` fact source sums what a campaign spent in USD, from the facts of other sources:

```toml
[plugins.fact_source]
use = ["campaign", "optimization", "leases", "models", "spend"]
```

The home's `config.toml` gives the price of one worker of each pool. It can also turn spend on for every campaign of
the home, as a [default](/reference/configuration) of their `piloop.toml`:

```toml
[plugins.executor.pools.agents]
usd_per_hour = 0.40

[plugins.fact_source]
use = ["campaign", "optimization", "leases", "models", "spend"]
```

`GET /v1/campaigns/enwik8/spend` answers each part and the sum:

```json
{
  "usd": 16.0,
  "parts": [
    {"fact": "compute_usd", "usd": 1.0, "as_of": "2026-10-27T18:12:15.480248Z"},
    {"fact": "models_usd", "usd": 15.0, "as_of": "2026-10-27T18:12:15.480248Z"}
  ],
  "per_keep_usd": 8.0
}
```

- `compute_usd`, from `leases`: each second that a worker held a job of the campaign, at the pool's `usd_per_hour`. A
  worker that holds several jobs splits each second evenly among them. The time that a worker holds no job is no
  campaign's.
- `models_usd`, from `models`: the tokens of each agent that ended, at the list price of its model. The
  [price list](/plugins/rules#price-lists) is that of [genai-prices](https://github.com/pydantic/genai-prices), which
  piloop bundles. This is the API-equivalent cost, not an invoice: a subscription bills otherwise.
- A pool or a model without a price makes its part unknown (`null`), and the sum too. An unknown value is never 0. An
  alias such as `sonnet` is no model id, so it has no list price. Give it one, in USD per million tokens:

  ```toml
  [plugins.fact_source.models]
  prices = { sonnet = { input = 3.0, output = 15.0, cache_read = 0.3, cache_write = 3.75 } }
  ```

- `per_keep_usd` is the sum per keep.
- `facts` in `[plugins.fact_source.spend]` names the parts. Add a value that a source reads, such as a cloud's bill
  below: `facts = ["compute_usd", "models_usd", "gpu_usd"]`.
- `hold_at = { spend = 1000 }` holds the campaign at that sum, as below.

## Spend outside piloop

GPU time and paid APIs are **facts** that a **fact source** reads. The built-in `command` source runs a command that
writes `{"metrics": {"<name>": <value>}}` to `$PILOOP_RESULT_FILE`. `spend` adds the fact to the sum, and `hold_at`
holds the campaign at a limit of the sum:

```toml
[plugins.stop_rule]
max_runs = 20
max_tokens = 50_000_000
hold_at = { spend = 1000 }                    # nothing new starts at this spend

[plugins.fact_source]
use = ["campaign", "optimization", "billing", "spend"]

[plugins.fact_source.billing]
provider = "command"
command = ["uv", "run", "python", "scripts/gpu_bill.py"]   # reports {"metrics": {"gpu_usd": 1012}}
metrics = ["gpu_usd"]
notices = { gpu_usd = [300, 600] }            # a note in the inbox as each one is passed

[plugins.fact_source.spend]
facts = ["gpu_usd"]                           # add "compute_usd" and "models_usd" with their sources
```

```text
- Campaign: active. Progress: run 2/20 · 0.0h · 0/50.0M tok · spend 1012/1000 (launches held: spend at its limit).
```

```text
comment#5 escalation on campaign#1 by daemon, 35s ago · p0, unacknowledged
The stop rule needs your decision before the campaign goes on.

spend reached its hold_at of 1000: nothing launches until you raise it and run piloop init

A. Change the rule in piloop.toml, then run piloop init. → The campaign goes on under the new rule.
B. Keep the rule as it is. → Nothing new starts until the rule lets it.
Answer: `piloop inbox choose 5 <A|B>`

Details:
Stop rule limits: spend reached its hold_at of 1000: nothing launches until you raise it and run piloop init
```

- The daemon reads the source every `interval` seconds (300 by default), at the repo's root, with the daemon's
  environment. Give it its keys as [secrets](/guides/secrets).
- A **hold** is not a stop. While the value is at its limit, or unknown, nothing new starts, and what runs finishes and
  is scored. An unknown value is never read as zero.
- To resume, raise the limit and run `piloop init`.
- `piloop campaign stop` stops a held campaign at once. `while_held` says whether its closing review runs anyway
  (`run`, the default), is skipped (`skip`), or waits for the hold to end (`wait`).

A plugin can add a fact source, such as a cloud's billing API, or another stop rule: see
[Rules and facts](/plugins/rules).
