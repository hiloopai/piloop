`[plugins.stop_rule]` in `piloop.toml` says when a campaign stops, and when it holds. The setup writes the hours and
the cap in USD of model tokens that you give it:

```toml
[plugins.stop_rule]
max_hours = 6
hold_at = { models_usd = 30 }      # nothing new starts at 30 USD of model tokens

[plugins.fact_source]
use = ["campaign", "optimization", "models"]
```

Any one limit stops the campaign. Without a limit, the campaign has no end. These are the limits of the built-in stop
rule, `limits`:

<Stop />

`piloop status enwik8` shows the progress against each limit:

```text
- Campaign: active. Progress: run 2/20 · 0.0h · 0/50.0M tok.
```

## What a stop does

The daemon tells the running implementers to save their work and stop, and ends them 10 minutes later
(`[agents] wrap_up_grace`). It drops the queued runs. Their submissions are still scored.

| Command | What it stops |
|---|---|
| `piloop campaign stop enwik8` | The campaign, as a limit does. |
| `piloop pause enwik8 --reason "<why>"` | New launches of one campaign, until `piloop resume enwik8`. |
| `piloop stop` | The daemon, not the campaigns: the next `piloop serve` continues them. |

To go on after a stop, raise the limits and run `piloop init`, or [reopen](/concepts/campaigns#reopen-fork-and-retire)
the campaign.

## A hold

A **hold** is not a stop. While a `hold_at` fact is at its limit, or unknown, nothing new starts. What runs finishes
and is scored. The daemon escalates once. At `hold_at = { spend = 1000 }`:

```text
comment#5 escalation on campaign#1 by daemon, 35s ago · p0, unacknowledged
The stop rule needs your decision before the campaign goes on.

spend reached its hold_at of 1000: nothing launches until you raise it and run piloop init

A. Change the rule in piloop.toml, then run piloop init. → The campaign goes on under the new rule.
B. Keep the rule as it is. → Nothing new starts until the rule lets it.
Answer: `piloop inbox choose 5 <A|B>`
```

## What a campaign spent

Each **fact source** reads a fact that a limit or a section can use:

| Source | Fact |
|---|---|
| `models` | `models_usd`: the tokens of each agent that ended, at the list price of its model. |
| `leases` | `compute_usd`: each second that a worker held a job of the campaign, at its pool's `usd_per_hour`. |
| `command` | Any fact that your own command reports, such as a GPU bill. |
| `spend` | `spend`: the sum of the facts in its `facts`, by default `compute_usd` and `models_usd`. |

`models_usd` is the API-equivalent cost from [genai-prices](https://github.com/pydantic/genai-prices), not an invoice:
a subscription bills otherwise. A model without a price makes the fact unknown, never 0. An alias such as `sonnet` has
no list price, so give it one, in USD per million tokens:

```toml
[plugins.fact_source.models]
prices = { sonnet = { input = 3.0, output = 15.0, cache_read = 0.3, cache_write = 3.75 } }
```

piloop reads each agent's tokens from its harness's session file when it ends, into `agent_sessions.usage`.
`max_tokens` limits their `total` over the campaign.

## Spend outside piloop

The built-in `command` source runs a command that writes `{"metrics": {"<name>": <value>}}` to `$PILOOP_RESULT_FILE`.
`spend` adds the fact to the sum, and `hold_at` holds the campaign at a limit of the sum:

```toml
[plugins.stop_rule]
hold_at = { spend = 1000 }

[plugins.fact_source]
use = ["campaign", "optimization", "models", "billing", "spend"]

[plugins.fact_source.billing]
provider = "command"
command = ["uv", "run", "python", "scripts/gpu_bill.py"]   # reports {"metrics": {"gpu_usd": 1012}}
metrics = ["gpu_usd"]
notices = { gpu_usd = [300, 600] }            # a note in the inbox as each one is passed

[plugins.fact_source.spend]
facts = ["models_usd", "gpu_usd"]
```

The daemon runs the command every `interval` seconds (300 by default), at the repo's root, with the daemon's
environment. Give it its keys as [secrets](/guides/secrets). `GET /v1/campaigns/enwik8/spend` returns each part and
the sum.

A plugin can add a fact source or another stop rule: see [Rules and facts](/plugins/rules).
