The **orchestrator** is the coding agent that you talk to. It answers what the other agents escalate, manages the
ideas and reports to you. Open your agent in the campaign repo and ask it to "orchestrate the piloop campaign". It
follows the `piloop-operate` skill, and loops on one command:

```bash
PILOOP_ACTOR=orchestrator piloop inbox wait enwik8 --timeout 1800
```

```text
candidate#2: bytes 2720458 over 1 eval: the best of the bytes track now, rank 1 of 2; vs parent +968317
campaign enwik8 stopped: max_runs: 1 runs
next: piloop inbox wait enwik8 --after 17
```

The wait returns on a new inbox item, score or stop, or at the timeout. Its last line is the next wait, with a
cursor, so nothing is lost between two waits. The orchestrator uses no tokens while it waits. The daemon runs without
one.

## Multiple orchestrators

Start each external agent from the campaign repository with a distinct positive seat number. For example, run these
in separate terminals on the campaign home:

```bash
piloop orchestrate 1 -- codex 'Orchestrate this campaign with the piloop-operate skill. You are seat 1.'
piloop orchestrate 2 -- codex 'Orchestrate this campaign with the piloop-operate skill. You are seat 2.'
```

The launcher runs the agent command you supply. Pass its usual tools, model and other options on that command line.
Each child gets `PILOOP_SEAT_NUM` and a stable `PILOOP_INBOX_ID`, also set as its `PILOOP_ACTOR`. Preserve that
identity in the agent's shell. Restart a seat with the same number to reuse its acknowledgements. Each seat reads
the outstanding inbox on startup and tracks its own wait cursor. Scope waits and messages to the campaign.

Both seats can steer all workers. For a 1:5 ratio, configure the implementer role for ten concurrent workers and
start two seats. Read the current board and consult peers before overlapping changes. The seats decide how to
divide work. Campaign messages reach peers. For one seat, use `piloop message enwik8 'Please review idea 12' --seat 2`.
The addressed message is recorded on the campaign thread and delivered to seat 2's inbox. Acknowledging a broadcast
clears it for that reader. The first escalation answer committed under the database write lock settles it for
everyone. Peers see the signed decision in their inboxes. Perform the action only after your answer is accepted.

## The inbox

The **inbox** is every comment that has a priority: 0 and 1 are urgent, 2 to 4 can wait.

```bash
piloop inbox
```

| Command | What it does |
|---|---|
| `piloop inbox show 5` | Shows the item and its thread. |
| `piloop inbox ack 5` | Marks it as seen, for you: the orchestrator still sees it. |
| `piloop inbox reply 5 "<text>"` | Answers it, which takes it out of every inbox. |
| `piloop message enwik8 "<text>"` | Writes to the orchestrator. Its next wait returns the message. |

```bash
piloop message enwik8 "Try a larger dictionary next"
```

```text
comment#2 message on campaign#1
```

## Comments

Agents and people talk through **comments** on a campaign, an idea, a run, a candidate or another comment.

| Kind | Use |
|---|---|
| `note` | Context, or what an agent tried and learned, on the board. The next run of the idea reads it. |
| `message` | Words to someone. On a running agent, its run or its idea, it reaches the agent at its next `piloop` command. On a campaign, it is for the orchestrator. |
| `decision` | A decision, with the reason and how to revert it. |
| `escalation` | A question that needs a decision. It holds no run. |

## Escalations

An agent asks for a decision with `piloop escalate`, in a form that says it in plain words:

```bash
piloop escalate campaign#1 --priority 1 <<'JSON'
{"ask": "Do you approve a longer timeout?",
 "why": "Each run takes 3 hours. The timeout is 1 hour.",
 "options": [{"choice": "Raise it to 4 hours.", "result": "Each run costs more."},
             {"choice": "Keep it.", "result": "The idea stops."}],
 "recommend": 0,
 "details": "run#41 timed out."}
JSON
piloop inbox show 1
```

```text
Do you approve a longer timeout?

Each run takes 3 hours. The timeout is 1 hour.

A. Raise it to 4 hours. (recommended) → Each run costs more.
B. Keep it. → The idea stops.
Answer: `piloop inbox choose 1 <A|B>`

Details:
run#41 timed out.
```

`piloop inbox choose 1 A` answers it, signed as you.

- Every escalation reaches you at once, through your [notifiers](/guides/notifications), whoever filed it.
- `[plugins.escalation]` sets the form and its limits.

## Decisions

The orchestrator decides what comes up, so work never waits for you. It records each decision that it takes for you as
a `decision` in your inbox:

```text
[<category>, reversible|irreversible] <what it decided, in one line>
Why: <the evidence, with ids>
Changed: <the rows, files, settings or commits>
Revert: <the command or edit that undoes it>
```

A change to a goal, a metric, a guardrail, the evaluate command or a stop condition has priority 0. A decision that
cannot be undone, and can wait, it leaves to you as an escalation. To revise a decision, reply to it: in `piloop watch`,
press `r`.

## Several campaigns

One daemon serves every campaign of a `PILOOP_HOME`. To improve two repos, set up a campaign in each. Two goals for the
same code, such as accuracy and cost, are [tracks](/concepts/pool#tracks) of one campaign. One agent can orchestrate
every campaign: ask it to "orchestrate all my piloop campaigns".
