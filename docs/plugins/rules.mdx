The best rule decides which candidate may be the best. The stop rule decides whether a campaign goes on. Both are
[pure](/plugins/overview#host-and-pure-contracts): piloop gives them data, and they return data. The fact sources
supply what a stop rule or a section reads.

## Best rules

The best of a track is the candidate with the best mean of its primary among those that may be best
([The pool](/concepts/pool#the-best)). For each confirmed candidate, piloop asks the best rule why it may not be best.
piloop gives the rule a `Case`: the scores of the candidate, the scores of the baseline, and the metrics that decide.
The rule returns a reason, or None when the candidate may be best. When the rule refuses a candidate that would be
the best, its worker hears the reason.

### Example: a gain of a fixed size

This rule [calls the built-in rule](/plugins/overview#call-a-built-in-provider) `baseline` and changes one thing: a
candidate whose gain over the baseline is below `min_gain` may not be best. `min_gain` is in the units of the primary
metric:

<ExampleMinGain />

```text
[plugins.best_rule]
provider = "min_gain"
min_gain = 1000
```

### The contract

A best rule is a [pure](/plugins/overview#host-and-pure-contracts) provider, a subclass of `BestRule`.

<ContractBestRule />

The rule decides only whether a candidate may be best. piloop decides when a candidate is confirmed, and ranks those
that may be best by their mean. `baseline` is the rule of a campaign without `[plugins.best_rule]`:
[The best](/concepts/pool#the-best) describes it.

## Stop rules

On each pass, the daemon asks the stop rule of each active campaign whether the campaign goes on, holds, or stops. piloop gives the rule a `StopCase`: the facts that the rule asked for. The rule returns one
of four answers:

<StopAnswers />

A hold is not a pause: piloop asks the rule again on each pass, and the hold ends when the rule answers `Go`.

The built-in rule is `limits`. It holds the campaign while a fact of `hold_at` is unknown or at its limit. Else it
stops the campaign at the first of its other limits that the campaign reaches.

### Example: end the campaign after a number of new bests

This rule stops the campaign after `bests` new bests. It [calls the built-in rule](/plugins/overview#call-a-built-in-provider)
`limits` and adds one limit, so the limits of `limits`, such as `max_hours` and `hold_at`, still apply:

<ExampleStopAfterBests />

```text
[plugins.stop_rule]
provider = "after_bests"
bests = 3
max_hours = 12
```

### Example: escalate when a new best costs too much

This rule compares the fact that `spend` names, since the latest new best, with its value per new best so far. Past
`escalate_at` times, it answers `Escalate` once for each new best; past `stop_at` times, it stops the campaign:

<ExampleBestCost />

```text
[plugins.stop_rule]
provider = "best_cost"
spend = "billing_usd"   # a fact that a Readings source reads, which has its growth since a new best
escalate_at = 2
stop_at = 4
```

### The contract

A stop rule is a [pure](/plugins/overview#host-and-pure-contracts) provider, a subclass of `StopRule`. Its fields are
its limits and other parameters. Most facts cost database queries on every pass, so piloop gets only those of
`reads`. `piloop status` and the briefs join the parts of `describe` into the progress line:
piloop formats no fact itself.

<ContractStopRule />

`Go.left` says how much of each fact is left before the rule stops the campaign. piloop starts no more runs than
`RUNS` leaves, and cuts each agent's timeout where `HOURS` runs out, so a run that starts just before the stop ends
with it. An agent whose start comes after the rule answers `Stop` never starts: the pass that stops the campaign
closes its row. `check_config` refuses a campaign that the rule cannot serve when the file loads: `limits` refuses a
`target` on a campaign of more than one track.

A fact is a typed key, `Fact[T]`, that a [fact source](#fact-sources) of the campaign supplies.
`case.facts.get(NEW_BESTS)` reads one, and `case.facts.get(reading('spend'))` one that a source reads by name. Every
fact that a rule reads needs a source in the campaign, or piloop refuses the configuration. The facts of the built-in
sources `campaign` and `optimization`, and the ratios over facts that a rule names (`spend`, what the campaign spent;
`cost`, the evaluator's metric of what one evaluation costs):

<Facts />

Each is None while a term is, or when its count is 0. A rule that reads a ratio asks for the facts of its terms.

`piloop campaign stop` stops the campaign whatever the rule answers, also when the rule holds it. `limits` is the
rule of a campaign without `[plugins.stop_rule]`: [Stop conditions and cost](/concepts/cost) lists its limits.

## Fact sources

A **fact source** supplies the facts that a stop rule or a section reads.

### Example: read what a billing endpoint says

```python
import json
import urllib.request
from pathlib import Path

from piloop.capabilities import FactReadError, Readings


class Billing(Readings):
    """``billing``: what a billing endpoint says that the campaign spent, as ``billing_usd``."""

    url: str

    def names(self) -> tuple[str, ...]:
        return ('billing_usd',)

    def read(self, repo: Path) -> dict[str, float]:
        try:
            with urllib.request.urlopen(self.url, timeout=30) as answer:
                return {'billing_usd': float(json.load(answer)['total'])}
        except (OSError, KeyError, ValueError) as e:
            raise FactReadError(f'{self.url}: {e}') from e
```

```toml
[project.entry-points."piloop.fact_sources"]
billing = "my_package:Billing"
```

```text
[plugins.fact_source]
use = ["campaign", "optimization", "billing", "spend"]

[plugins.fact_source.billing]
url = "https://billing.example.com/campaigns/enwik8"

[plugins.fact_source.spend]
facts = ["billing_usd"]
```

`spend` sums the facts that it names, and `hold_at = { spend = 1000 }` then holds the campaign at that sum.

A fact source is a subclass of `FactSource`. A campaign without `[plugins.fact_source] use` has every installed
source that is on by default (`DEFAULT`): `campaign`, its hours and tokens, and `optimization`, its research. A list
that adds a source names those too. Two sources never supply the same fact.

The daemon reads a `Readings` source every `interval` seconds. It implements `names` and `read`, and piloop does the
rest: each reading is a `fact.read` event on the campaign, a note goes to the inbox at each of its `notices`, and one
escalation when its readings start to fail.

## Price lists

A **price list** says what a model's tokens cost at its vendor's list price. The `models` fact source asks it for each
agent that has no price in its `prices`:

```toml
[plugins.price_list]
provider = "genai_prices"   # the default
```

The built-in `genai_prices` reads the prices that the [genai-prices](https://github.com/pydantic/genai-prices) package
bundles, with no network. Each harness names its model as its vendor's API does (`Harness.model_id`): `claude` at
`anthropic`, `codex` at `openai`, and `pi` by the provider of `<provider>/<id>`. A price list that has no price for a
model returns None, and the spend of its campaign is unknown.

## Launch policies

A **launch policy** picks the campaign that each free agent slot goes to. It is one per home, in `config.toml`, and
holds the limits of the startup breaker:

```toml
[plugins.launch_policy]
provider = "fewest_live"   # the default
startup_breaker = 3        # this many failed starts of a campaign's agents...
startup_window = "PT10M"   # ...within this window pause its launches
```

The built-in `fewest_live` gives each slot to the waiting campaign with the fewest live agents. A policy reads its own
keys for anything else it needs, such as a priority or a weight by campaign name. Returning `None` leaves the slots
free, which is how a policy sets a quota.

<ContractLaunchPolicy />

## Harness choices

A **harness choice** picks the harness of the role's rotation that the next agent runs on. Each campaign picks its own,
in `piloop.toml`:

```toml
[plugins.harness_choice]
provider = "round_robin"   # the default
```

The built-in `round_robin` gives the n-th agent of a role the n-th harness. A harness whose session the agent can
resume comes first, and a full harness passes its turn. A harness that `piloop launch --harness` names is never
replaced.

<ContractHarnessChoice />

## Liveness policies

A **liveness policy** decides when the daemon ends an agent that is stuck. Each campaign picks its own, in
`piloop.toml`:

```toml
[plugins.liveness]
provider = "probes"        # the default
start_within = "PT15M"     # run within this long of a worker taking the job...
quiet_for = "PT20M"        # ...and write to the session file at least this often
escalate_at = 2            # the stall of an idea that tells a human, once
```

On each wind-down pass, the daemon asks the policy about each starting or running agent. `Alive` lets it go on, and
says when to ask again. `Stalled` ends it: its run ends `stalled`, which is not an attempt, and its idea opens again with a
note that says why. `EscalateStall` tells a human, once for each reason, and then does its `then`. The role's timeout still
bounds every agent.

The built-in `probes` counts the start from when a worker took the job, so an agent that waits for a free worker is not
stuck. A tool call writes nothing until it returns: set `quiet_for` above the longest one.

<ContractLiveness />

## Escalation policies

An **escalation policy** decides what an escalation holds, who sees it when, and how it shows. `[plugins.escalation]`
in `piloop.toml` chooses it. `structured`, built in and the default, asks for one decision in plain words, and sends
every escalation to a human at once ([Escalations](/concepts/orchestrator#escalations)). A provider that lets an
escalation wait, so that your orchestrator can answer it first, changes one method:

```python
from datetime import datetime, timedelta

from piloop.capabilities import At, Escalated, Structured, ToHuman


class Later(Structured):
    """``later``: the form of ``structured``, and an escalation reaches a human 30 minutes after it was filed."""

    def reach(self, item: Escalated, now: datetime) -> ToHuman:
        return At(item.filed + timedelta(minutes=30))
```

```toml
[project.entry-points."piloop.escalations"]
later = "my_package:Later"
```

piloop stores the form that `form` returns, and never reads it. The notifiers, `piloop inbox show` and the API show
the `EscalationView` that `view` returns, so a provider with other fields shows on every surface.
