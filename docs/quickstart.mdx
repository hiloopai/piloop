You run piloop through one coding agent. You tell it the goal, and it sets up the campaign and runs it for you.

<Steps>
  <Step title="Install piloop">
    ```bash
    curl -fsSL https://raw.githubusercontent.com/hiloopai/piloop/main/install.sh | sh
    ```

    The installer installs uv, the `piloop` CLI and the piloop skills for each coding agent on your `PATH`. With uv
    already installed, you can install only the CLI and the skills:

    ```bash
    uv tool install piloop
    piloop install-skills
    ```
  </Step>
  <Step title="Open your agent in your repo">
    Start Claude Code, Codex, pi, Gemini CLI or Cursor in the repo to improve. This is the only agent that you talk
    to. The implementers run on Claude Code and Codex, so install at least one of them.
  </Step>
  <Step title="Tell it what to improve">
    Say "piloop", so that the agent uses the piloop skills:

    ```text
    Use piloop to improve the holdout accuracy of the model in train.py.
    ```

    To try piloop on an example first, ask for "the enwik8 example campaign from piloop".
  </Step>
</Steps>

## The setup

The agent follows the `piloop-setup` skill:

1. It checks git, uv and the logins of the coding agent CLIs. It asks you to log in only where a CLI needs a browser.
2. It reads your repo and interviews you. It asks only what the repo does not answer.
3. It writes `brief.md` for the implementers, `piloop.toml` with the metrics and limits, and the evaluate command,
   and shows you the files.
4. It runs `piloop init .`, which starts the daemon and measures the baseline. A baseline that surprises you usually
   means that the evaluate command is wrong.
5. It becomes the [orchestrator](/concepts/orchestrator), in this session or in a background subagent.

The interview covers:

| Topic | The agent asks |
|---|---|
| Objective | The metric to improve, its direction, and what "done" is. |
| Measurement | The command that measures it, how long it takes, and how noisy it is. |
| Guardrails | What must not get worse, such as latency or size, and by how much. |
| Scope | The files that implementers may edit, the files they must not touch, and forbidden techniques. |
| Hours and money | The campaign's hours (6 is suggested) and its cap in USD of model tokens. |
| Width | How many implementers at a time: 2 by default, or 10 for a better result at more cost. [Choose a setup](/guides/choose-a-setup) has the numbers. |
| Escalation | What the agent must ask you, and what it may decide alone. |

The daemon enforces only the limits in `piloop.toml`. A limit that is only in `brief.md` is a request to the agents.

## While the campaign runs

Your agent waits on the inbox with `piloop inbox wait`, so it uses no tokens while nothing happens. It answers
escalations and records each decision that it takes for you in your inbox, with how to revert it. It leaves to you
the decisions that cannot be undone.

To check in, ask any agent with the piloop skills, also in a new session: "How is the campaign going?" To look
yourself, run `piloop watch` ([Watch and review a campaign](/guides/watch)).

## Stop

The campaign ends by itself at the limits of `[plugins.stop_rule]` in `piloop.toml`
([Stop conditions and cost](/concepts/cost)). To end it sooner, ask your agent, or run
`piloop campaign stop <campaign>`.

`piloop stop` stops the daemon, not the campaigns: the next `piloop serve --detach` continues them.
